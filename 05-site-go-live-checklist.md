# 05 · Site Go-Live Checklist

Used for every one of the 60 sites. A site only goes live when every item in the "Ready" column is ticked.

## T-14 days: Preparation
- [ ] Site confirmed in wave schedule and shared with Area Manager
- [ ] POS API credentials received and tested
- [ ] Broadband and network check passed
- [ ] Site GM booked onto training
- [ ] Go-live pack sent to Site GM

## T-2 days: Readiness Review
- [ ] Test data sync completed successfully
- [ ] Yesterday's test data matches POS end-of-day report
- [ ] Site GM training completed
- [ ] Rollback steps confirmed with integration team
- [ ] Support rota confirmed for go-live day

## Go-Live Day (before opening)
- [ ] Connector switched to live mode
- [ ] First live transaction received by the platform
- [ ] Site GM can log in and see their dashboard
- [ ] 5-minute shift briefing delivered to the team
- [ ] Go-live confirmed in the project tracker

## Day +1 to +7: Hypercare
- [ ] Daily reconciliation vs. POS end-of-day report (target ≥ 99.5% match)
- [ ] Any issues logged and triaged within 4 working hours
- [ ] Day-7 check-in call with Site GM
- [ ] Pulse survey sent

## Rollback Triggers
Roll back to manual reporting if **any** of these happen:
- POS performance is affected during trading
- Data accuracy is below 98% for two consecutive days
- A critical defect cannot be fixed within one working day

> **Why a checklist matters:** the 60th go-live should be as reliable as the first. A checklist turns lessons from the pilot into a repeatable standard.
